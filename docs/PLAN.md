# Implementation plan

Status: active, 2026-11-16. Repository setup, local checks, import recovery, hosted macOS/Linux CI and the three-target packaging dry run passed. The production milestones below remain open. Follow [PRODUCT](PRODUCT.md) for accepted scope and [the preserved handoff](research/showboat-like-tool/docs/09-NEXT-SESSION.md) for provenance.

## Ordered milestones

| Milestone | Scope | Completion evidence |
| --- | --- | --- |
| M1 — Freeze compatibility | Select and verify the Showboat pin; enumerate syntax, errors, files, metadata and remote behavior; assess CLI parsing dependency | [Compatibility matrix](plans/compatibility.md) expanded into executable differential cases against an exact upstream build; intentional differences isolated |
| M2 — Document CLI | Implement all pinned commands and options, source-preserving edits, cold execution, images, replay/diffs, extraction and remote streaming | Every M1 case passes; originals remain unchanged on verify/copy; no external Showboat requirement in product operation |
| M4 — JVM and Node execution | Native forwarding, managed session scopes, runtime SDKs, bounded scheduling, resource custody and cold routing | Independent packaged-cold parity, actual warm-route assertions, no-retry effects guard, lazy/large-stream tests, state/resource and owner-loss controls on macOS/Linux |
| M5 — Python extension | Implement a cooperative Python SDK/application boundary | Same host contract and parity/lifecycle suite, with explicit Python state/resource limits; no runtime-specific host branch |
| M6 — Product qualification | Pin platform matrix, qualify distribution, audit dependencies/licenses and measure complete-session performance | Clean standalone installs, recorded binary/linkage sizes, repeatable warm/cold ratios with route counts and preparation/replay separated |

## Immediate work: M1

- Confirm the proposed v0.6.1/commit baseline against upstream source and the consumer pin, then record the exact executable/toolchain identity.
- Enumerate all command forms, option positions, stdin/exit/error semantics and filesystem/HTTP effects; implement the oracle harness before product command code.
- Evaluate `clap` or another parsing approach against this inventory. Choose the smallest solution that preserves required behavior; do not inherit LOCmetry's dependency graph or assume parser defaults match upstream.
- Establish timestamp/UUID/branding normalization narrowly; preserve legacy metadata exactly. Select dependencies for demonstrated needs only.
- Turn each matrix row into discriminating tests, including negative controls, and keep production integration tests in one binary.

## Working discipline

Use red/green implementation and finite oracles. Review protocol/lifecycle and final compatibility claims adversarially before accepting their milestones. Keep qualification results tied to revisions and artifacts; a historical pass or configured workflow does not satisfy a new gate. Save new evidence outside the immutable snapshot and time comparisons alone on a near-idle host.

## Concrete lessons from related implementations

Source and test inspection on 2026-11-16 used Runme `18a321dfdaa8f4e1eba33b28e7bf50460d9ad597` and speedrunner `9abaf508c3e039c89d1bb43542189a7dcec086c2`. No upstream code was executed, copied or qualified here. These are planned acceptance controls and design choices, not new implemented capabilities. Do not claim novelty for native distribution or persistent runtimes individually, or superior size/performance without measurement.

| Milestone / lesson | Adaptation and discriminating acceptance control | Source |
| --- | --- | --- |
| M1/M2 — Preserve surrounding bytes | Adapt exact round-trip cases: unknown/invalid frontmatter, zero/one/multiple trailing newlines, CRLF, tabs, Unicode and nested fences. Assert that only the intended managed region changes, subject to the pinned upstream contract. Avoid whole-document reserialization and automatic ANSI stripping. | Runme [preservation tests](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/document/editor/editor_test.go#L253-L289), [newline tests](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/document/editor/editor_test.go#L431-L495), [serializer](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/document/editor/cell.go#L338-L483) |
| M1/M2 — Preserve shell semantics | Differentially test `false; printf ok`, `false \| true`, exports across separate blocks and cwd/PWD changes. Reusing an application worker must not silently share shell state, add failure flags or inject environment-export traps. | Runme's deliberate [shell/session behavior](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/command/command_inline_shell.go#L83-L148) |
| M3 — Prepare an immutable invocation | Separate original native argv/context from resolved forwarding/worker configuration. Preparation occurs once, preserves caller-owned input, and failure/classification refusal leaves a payload side-effect marker absent. Preserve the absolute cold launcher independently. | Runme [invocation types](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/internal/execution/program.go), [preparation tests](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/command/preparation_test.go#L51-L145) |
| M3 — Make the execution boundary explicit | Model eligibility, readiness and acceptance separately. Inject disconnects before and after every transition and count durable side effects. Keep mdrun's strict no-fallback-after-acceptance rule; speedrunner's explicit refusal after its go message is a different protocol contract. | speedrunner [handshake and completion branches](https://github.com/anthonyGosme/speedrunner/blob/9abaf508c3e039c89d1bb43542189a7dcec086c2/client/src/main.rs#L863-L977) |
| M3/M4 — Bound stream ownership and completion | Require readiness before granting application stream ownership; a stalled startup must not retain pipe endpoints or consume stdin. Drain accepted output before EOF/acknowledgement using truly bounded queues. Keep any stream error regardless of completion order; test cancellation after one stream has completed and a slow reader under sustained output. | speedrunner [readiness before descriptor transfer](https://github.com/anthonyGosme/speedrunner/blob/9abaf508c3e039c89d1bb43542189a7dcec086c2/client/src/main.rs#L890-L927); Runme [drain test](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/runnerv2service/buffer_test.go#L10-L38), [growing buffer](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/runnerv2service/buffer.go#L35-L59), [completion aggregation](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/runnerv2service/execution.go#L174-L207) |
| M4 — Make warm routing testable | An expected-warm assertion must fail before payload execution when eligibility would select cold. Record a stable reason separately from captured stdout/stderr. Explicit cold takes precedence and starts no warm machinery. Do not adopt speedrunner's diagnostic exit numbers as the public contract without compatibility checks. | speedrunner [cold selection](https://github.com/anthonyGosme/speedrunner/blob/9abaf508c3e039c89d1bb43542189a7dcec086c2/client/src/main.rs#L694-L743), [require-fast branch](https://github.com/anthonyGosme/speedrunner/blob/9abaf508c3e039c89d1bb43542189a7dcec086c2/client/src/main.rs#L981-L1001) |
| M4 — Qualify cold execution beyond argv | Compare native/cold behavior for closed streams, extra inherited descriptors, broken pipes, ignored signals and signals during launch. Check the original launcher's effective SIGPIPE behavior rather than assuming the Rust process's inherited state is faithful. | speedrunner [native exec and SIGPIPE restoration](https://github.com/anthonyGosme/speedrunner/blob/9abaf508c3e039c89d1bb43542189a7dcec086c2/client/src/main.rs#L1067-L1088) |
| M4 — Observe full cleanup | Retain fixture exclusion through observed descendant/worker cleanup, even if command output and status arrived earlier. Test held-open pipes, abrupt owner loss and a descendant attempting a delayed write; check both observed exit and absence of the write. Do not copy early teardown completion or tests that intentionally permit surviving descendants. | Runme [isolated descendant scenarios](https://github.com/runmedev/runme/blob/18a321dfdaa8f4e1eba33b28e7bf50460d9ad597/command/command_lifecycle_unix_test.go#L97-L166); speedrunner [early completion paths](https://github.com/anthonyGosme/speedrunner/blob/9abaf508c3e039c89d1bb43542189a7dcec086c2/client/src/main.rs#L938-L977) |
| M4/M5 — Test hidden retained state | Qualify frozen clocks/random generators, externally changed files, rotated log handles, temporary directories, import-time environment and terminal checks. Unqualified differences must select cold or invalidate the session; automatic import learning and long-lived per-user daemons remain outside the initial design. | speedrunner [documented limits](https://github.com/anthonyGosme/speedrunner/blob/9abaf508c3e039c89d1bb43542189a7dcec086c2/docs/GUIDE.md#known-limits) |
| M4/M6 — Add reproducible disruption stress | Use seeded, bounded concurrent document sessions while stopping/killing workers and changing artifact identities. Each invocation has its own side-effect marker and independent packaged-cold byte/status oracle; failures retain the seed and event trace. Test overlap within one worker as rejection, not supported concurrency, and assert warm counts so all-cold fallback cannot pass the acceleration gate. | speedrunner [stress harness](https://github.com/anthonyGosme/speedrunner/blob/9abaf508c3e039c89d1bb43542189a7dcec086c2/tests/test_stress.py#L109-L187) |

Source-level concerns in Runme's completion aggregation motivate the error-order/cancellation controls above; they were not runtime-reproduced and are not reported as certified upstream defects. Its dynamic buffer's initial capacity is not a memory bound. Neither source is adopted as mdrun's lifecycle oracle: the consumer requirements and independently observable outcomes remain authoritative.
