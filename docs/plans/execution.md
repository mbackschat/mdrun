# Execution implementation and qualification

## M3: host and SDK vertical slice

The reviewed [proposed session contract](session-protocol.md) supplies the initial CLI, binding, wire and custody design. It remains unqualified: implement and test its proof obligations before freezing SDK APIs. Host-owned context capture keeps generic environment work out of consumer harnesses. An ambiguous disconnect after dispatch must fail without retry even when the acceptance response was lost.

The experimental native host and [Node SDK](../../sdk/node/README.md) now have local macOS controls for sequential reuse, refusal followed by independent cold execution, changed-environment routing, explicit cold, bound document verification, multi-megabyte binary streams, unused open stdin, lost acceptance without duplicated effects, and idle workers beyond the startup timeout. Private native transport preserves OS-string cwd/argv/environment bytes and transfers original descriptors to custody. Public and hidden CLI options use clap; forwarded application flags are uninterpreted. These results advance the checklist without completing M3 or freezing the SDK.

Independent HIGH review found and guarded native cwd serialization loss, cancellation masked by exit zero or observed before launch, final-release admission ordering, and late retained SDK operations after orderly shutdown. Native guards also exposed macOS socket descriptors returning a different `tcgetpgrp` error from pipes; terminal classification now uses `isatty`. The Node fixture explicitly supplies the selected runtime's observed macOS text-encoding environment value; the host does not ignore that variable or other context differences. Ordinary shell-wrapper context changes still need consumer parity evidence.

Local checkpoint on 2026-11-16, macOS 27.2.1 arm64, Rust 1.98.0 and Node 26.10.0: 58 Rust unit tests and 40 ordinary integration tests pass; six additional Rust-host/Node integration controls pass when explicitly enabled; the independent Node fake-host suite passes 33 tests. Formatting, Clippy and release compilation pass, and the release executable passes all 75 retained Showboat behavioral differential cases. Its SHA-256 is `76677ea4cc8067e240e1f1496162e56421703cc4dab6e9920c4a1c60a2007261`. These counts include test fixture entry points and do not establish every outstanding proof obligation.

A subsequent actual-host cold-session control passes locally: kill only the host while a payload descendant survives, observe the declared TCP listener still excluded, then require descendant exit and certified group cleanup before release. A direct-owner negative control detects the early-release behavior this design prevents. Its two focused test entries include one fixture entry point; bounded self-expiry and direct `Child` handles avoid teardown signals to remembered PIDs/groups. Sampling establishes observed ordering, not continuous-time proof; hosted qualification remains required.

An additional actual-host Node control confirms that caught late SDK output after orderly shutdown fails the session even when the author and application both returned zero. The host observes the worker's real exit status separately from application completion and reports successful cleanup independently from that infrastructure failure.

Additional controls kill the real host, worker or author during an accepted warm invocation with a surviving same-group descendant. They sample the declared listener's continued exclusion through descendant termination and require certified cleanup before release. Direct-owner negative controls demonstrate early release without custody; watchdog-expiry markers prevent self-termination from masquerading as successful cleanup. Worker/author loss also requires a failed session report, with the author's SIGKILL reported explicitly. Four focused entries, including the native author helper, pass; independent HIGH review corrected readiness-publication and expiry-oracle weaknesses. These are cooperative same-group observations, not proof of uninterrupted exclusion between samples or containment of escaped groups. macOS/Linux CI (historical run) and CodeQL (historical run) pass at `55d7b38`. Linux first exposed an exit-after-open procfs race; both production and independent observation now accept only `ENOENT`/`ESRCH` as disappearance. A Linux retained-stat-descriptor regression reproduces `ESRCH` deterministically; other observation errors remain failures.

Hosted qualification at `036414e` passes CI (historical run) and CodeQL (historical run), including JavaScript SDK scanning. macOS 15 passes 59 unit and 42 ordinary integration tests; Ubuntu 24.04 passes 58 unit and 44 ordinary integration tests, including native-byte filename/cwd controls. Both run six Rust-host/Node controls, the Node fake-host suite, release compilation and the retained Showboat differential. The subsequent late-shutdown host guard is additionally local-qualified; these foundation results do not complete the remaining M3 gates.

## M4/M5: SDKs and scheduling

The experimental [Java 21 SDK](../../sdk/jvm/README.md) is implemented with a separate hash-locked Jackson core dependency. All SDK threads start before the application factory establishes its resource baseline. The independent wire-peer suite passes 11 tests locally on 2026-11-16, covering repeated calls and nonzero status, refusal, multi-megabyte binary streams, fresh EOF, shared output sequence, strict framing/schema/Base64, admission/release ordering, reset failures, control loss and retained-stream lifetime. It caught an orderly-shutdown bug where intentional socket closure was reported as peer loss; the corrected distinction and malformed-message handling passed an independent HIGH source review. Twelve tooling tests pass with Java 21 enabled, including reproducible SDK-only packaging and rejection before compilation of invalid dependency age/hash/POM/notices. These results leave application cleanup and consumer gates open.

An independent packaged-cold fixture and a cooperative worker use the same application class but separate entry points and classpaths; cold contains neither SDK nor Jackson. The Rust-host qualification compares seven calls, including changed file contents, binary streams, a 512 KiB input, and failure followed by success, while asserting zero cold workers and exactly one reused warm worker. An actual-host retained-output guard requires session failure after application/author success when the JVM exits 70 during shutdown. All three focused entries, including the native author helper, pass locally; formatting, Clippy, 59 unit tests and 42 ordinary integration tests also pass. Runtime qualification is explicitly enabled; ordinary Cargo tests need no JVM.

Hosted CI (historical run) and CodeQL (historical run) pass at `0defeab` on 2026-11-16. macOS 15 and Ubuntu 24.04 both pass all 11 JVM wire tests, three Rust-host/JVM entries, 12 tooling tests, the existing Node controls and the retained Showboat differential; Java source scanning also passes. Both runners download the canonical Jackson artifact with the locked SHA-256 and produce the same SDK jar hash `e5f63215b9f3ff85ba3a367d31ce660f72fd7f8616bc3ec71ffe45722f467ffc`. These observations qualify this SDK foundation and dependency provenance, not M3 completion or arbitrary Java applications.

- [ ] Node SDK: load an explicit handler once and await sequential invocations. Keep loaded code immutable; reread mutable input/configuration. Qualify timers, listeners, unresolved work, children, failures and late output. Module reload or a VM context is not a general reset strategy.
- [ ] Python SDK: load an explicit factory with fresh request-owned arguments/streams. Ordinary failures return status; uncaught exceptions and invalid completion poison reuse. Qualify threads, process exits and native-extension limits; do not promise automatic reuse of arbitrary scripts.
- [ ] Run shared conformance through every SDK without runtime-specific host branches. Compare independently launched packaged cold, assert actual routing/reuse, and check changed inputs plus failure-then-success sequences.
- [ ] Bound parallel independent document sessions. Stop admission on failure, drain launched peers and aggregate reports; keep worker calls sequential and preserve shared-resource exclusions.
- [ ] Provide a minimal application-adapter example and SDK guide. Keep protocol, relay, supervision, scheduling and report production out of consumer code.
